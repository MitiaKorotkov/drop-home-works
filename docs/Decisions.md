# Сайт для сдачи домашних работ: требования

Документ фиксирует принятые решения. Нерешённое собрано в разделе «Открытые вопросы» в конце.

## Общее

- Один учитель, несколько классов.
- Сайт размещается на домашнем сервере и доступен из интернета.
- Frontend — React SPA, его пишет отдельный разработчик. Backend — Go и PostgreSQL.

## Доступ

- Регистрации нет. Учётные записи учеников создаёт учитель и сам раздаёт логины и пароли.
- Ученик входит по логину и паролю. Он видит только задания своего класса и только свои сдачи.
- Учитель входит так же, по логину и паролю. Его учётная запись создаётся консольной командой при установке сервера; через сайт её создать нельзя.
- Пароли хранятся только в виде хэша, поэтому посмотреть пароль ученика потом нельзя. Если ученик забыл пароль, учитель сбрасывает его и выдаёт новый.
- Число попыток входа ограничено, чтобы пароли нельзя было перебрать.
- Права проверяет сервер на каждом запросе. То, что страниц учителя нет в интерфейсе ученика, защитой не считается.

## Сущности

- **Класс** — название, например «7А».
- **Ученик** — имя и фамилия, логин, пароль. Состоит ровно в одном классе.
- **Задание** — название, текстовое описание, необязательные файлы, количество задач. Выдаётся одному или нескольким классам, у каждого класса свой дедлайн.
- **Сдача** — работа ученика по заданию: один PDF-файл, состояние и балл. Хранится только последняя версия файла.

## Состояния задания для ученика

| Состояние | Когда |
|---|---|
| Не сдано | Файла нет, дедлайн не прошёл |
| Сдано | Файл загружен, учитель ещё не взял его на проверку |
| На проверке | Учитель отметил, что проверяет работу |
| Проверено | Учитель выставил балл |
| Просрочено | Файла нет, дедлайн прошёл |

- Загрузить файл можно только в состояниях «Не сдано» и «Сдано» и только до дедлайна.
- Как показывать состояния (цвета и прочее), решает фронтенд.
- Состояние считается от текущего дедлайна. Если учитель перенёс дедлайн на более поздний срок, «Просрочено» снова становится «Не сдано» и загрузка опять доступна.

## Сценарий ученика

1. Открывает сайт и входит по логину и паролю.
2. Видит список заданий своего класса: название, дедлайн, состояние и, если работа проверена, балл в виде «7/10». Может открыть описание задания и скачать его файлы.
3. Чтобы сдать работу, выбирает PDF-файл. Предпросмотр показывает браузер, а на сервер файл уходит только по кнопке «Отправить». Черновиков на сервере нет.
4. Пока учитель не взял работу на проверку и дедлайн не прошёл, может отправить её повторно: новый файл заменяет старый. После отметки «На проверке» или выставления балла замена недоступна, иначе балл относился бы к файлу, которого больше нет.
5. После дедлайна загрузка заблокирована. Время проверяет сервер по своим часам, а не по часам ученика. Работа сдана в срок, если сервер начал принимать файл до дедлайна, даже если загрузка закончилась позже.
6. Может скачать свой отправленный файл, чтобы убедиться, что отправил правильный. Чужие файлы ему недоступны.

## Сценарий учителя

**Классы и ученики**

- Создать класс.
- Добавить ученика в класс: имя и фамилия, логин, пароль.
- Переименовать ученика, удалить ученика, перевести его в другой класс.
- Сбросить ученику пароль.

**Задания**

- Создать задание: название, описание, файлы, количество задач.
- Выдать задание одному или нескольким классам и для каждого указать дедлайн.
- Отредактировать задание: название, описание, файлы. Выдать его ещё одному классу.
- Удалить задание.
- Перенести дедлайн для класса. Для отдельного ученика дедлайн не переносится.
- Количество задач после создания задания изменить нельзя.
- Снять задание с класса, которому оно уже выдано, нельзя.

**Проверка**

- Выбрать класс и задание и увидеть всех учеников класса с их состоянием, включая тех, кто не сдал.
- Открыть присланный PDF.
- Отметить работу как «На проверке».
- Снять отметку «На проверке», например если она поставлена по ошибке. Работа возвращается в состояние «Сдано», и до дедлайна ученик снова может её заменить. С уже проверенной работы отметку снять нельзя.
- Выставить балл — целое число от 0 до количества задач в задании. Отметка «На проверке» необязательна, балл можно выставить сразу. Выставленный балл можно исправить.

**Удаление и перевод**

- Удалить задание или ученика можно, даже если у них есть сдачи. Фронтенд просит подтверждение, сдачи и их файлы удаляются вместе с ними.
- При переводе ученика в другой класс его сдачи сохраняются. Ученик видит задания нового класса; сдача по заданию, выданному обоим классам, остаётся видна. В списках старого класса ученик больше не показывается.

## Ограничения

- Сдача — ровно один PDF-файл, до 20 МБ. Сервер проверяет, что это действительно PDF, по содержимому файла, а не по расширению.
- Файлы задания — любого типа, до 50 МБ каждый.
- Дедлайн — дата и время.
- Логин — латинские буквы, цифры, точка, подчёркивание и дефис, от 3 до 32 символов. Регистр не важен: `Ivanov` и `ivanov` — один логин.
- Пароль — от 8 до 128 символов

## Развёртывание и API

- Сайт работает только по HTTPS, иначе пароли передаются открытым текстом.
- SPA и API отдаются с одного домена. Reverse proxy (Caddy) отдаёт статику фронтенда, перенаправляет `/api/*` в Go-сервер и сам получает сертификат Let's Encrypt. CORS не нужен.
- Сессия хранится в HttpOnly cookie, фронтенд токенов не хранит.
- При локальной разработке dev-сервер фронтенда перенаправляет `/api` на локальный бэкенд, поэтому код фронтенда одинаков локально и на сервере.
- API описан в OpenAPI (`api/openapi.yaml`). Спецификация — источник истины: любое изменение API сначала вносится в неё. Go-код бэкенда и TS-типы фронтенда генерируются из неё.
- Ошибки возвращаются в едином JSON-формате с машинным кодом (RFC 9457). Даты — в формате RFC 3339 с часовым поясом. 401 означает «вход не выполнен», 403 — «нет прав».
- Известный риск: если домашний сервер или интернет недоступен перед дедлайном, ученики не смогут сдать работу. Выход — перенести дедлайн для класса.

## План развития

- Переход на новый учебный год: переименование классов (7А → 8А), архив прошлого года, удаление классов.

## Не входит в первую версию

- Самостоятельная регистрация и восстановление пароля по почте.
- Смена пароля самим учеником.
- Несколько учителей.
- Несколько файлов или фотографии в одной сдаче.
- Перенос дедлайна для отдельного ученика.
- Изменение количества задач и снятие задания с класса.
- Комментарии учителя и возврат работы на доработку.
- Уведомления (почта, мессенджеры).

## Открытые вопросы

### Размещение на домашнем сервере

Эти вопросы не влияют на код и отложены. Решить их нужно до того, как на сайте появятся настоящие ученики, а резервные копии — обязательно до этого момента.

1. **Белый IP.** Проверить, выдаёт ли провайдер белый IP и меняется ли он. Если IP серый (CGNAT), нужен белый IP от провайдера, туннель или VPS.
2. **Адрес сайта.** Купить домен или взять бесплатный поддомен у DDNS-сервиса.
3. **Резервные копии.** Куда копировать базу и файлы и как часто. Предложение: каждую ночь, хранить 14 последних копий, хотя бы одна копия — не дома.
4. **Срок хранения файлов.** Предложение: до конца учебного года; удаление решается вместе с переходом на новый год.
