## 4. Аутентификация

- [x] Генерация сервера, подключение под /api, ошибки в формате RFC 9457.

- [x] Консольная команда создания учителя. Пароль не передаётся аргументом: иначе он попадёт в историю shell и в список процессов.

- [ ] Вход: логин приводится к нижнему регистру. Ответ для «нет такого логина» и для «неверный пароль» одинаковый и по содержанию, и по времени: при несуществующем логине всё равно считается хэш.
- [ ] Выход: сессия удаляется, cookie очищается.
- [ ] «Кто я».
- [ ] Middleware: пользователь по сессии попадает в контекст запроса, отдельно проверяется роль.
- [ ] Лимит попыток входа (в памяти процесса).
- [ ] `http.CrossOriginProtection`.
- [ ] Тесты: неверный пароль, несуществующий логин, истёкшая сессия, запрос без cookie, ученик на эндпоинте учителя.

## 10. Развёртывание

- [ ] Закрыть отложенные вопросы из [Decisions.md](Decisions.md): IP, домен, бэкапы, срок хранения.
- [ ] Dockerfile: многоэтапная сборка, минимальный образ, запуск не от root.
- [ ] compose для сервера: Postgres, бэкенд, Caddy, тома для базы и файлов.
- [ ] Секреты и доступ к базе:
  - пароль базы передаётся секретами compose (файлы в `/run/secrets/`), а не переменной окружения: так его нет в `docker inspect` и в окружении процесса;
  - файлов секрета два, с одним и тем же паролем. Postgres читает свой через `POSTGRES_PASSWORD_FILE`, в файле только пароль. Приложение — через `PGPASSFILE`: pgx читает его сам, кода не нужно, но файл в формате `.pgpass` (`host:port:db:user:password`). Пароль из `DATABASE_URL` тогда убирается;
  - у каждого файла секрета права `600`, владелец — UID процесса внутри контейнера, который его читает (у Postgres и приложения UID разные, поэтому один общий файл не подойдёт). Иначе будет «permission denied». Проверить на месте, что оба контейнера читают свой секрет;
  - `.env` на сервере — права `600`, владелец — пользователь, который запускает `docker compose`;
  - пароль длинный и уникальный, сгенерирован, а не придуман;
  - порт 5432 наружу не публикуется: база доступна только из сети compose.
- [ ] Caddyfile: `/api/*` на бэкенд, статика фронтенда с переходом на `index.html` для маршрутов SPA, HTTPS.
- [ ] Бэкап по расписанию: сначала `pg_dump`, потом копия папки с файлами.
- [ ] Проверить восстановление из бэкапа на чистой машине. Непроверенный бэкап — не бэкап.
- [ ] Создать учётную запись учителя на сервере.
- [ ] Открыть сайт с телефона через мобильный интернет, не из домашней сети.

**Готово, когда** ученик извне может войти и сдать работу, а бэкап восстанавливается.
