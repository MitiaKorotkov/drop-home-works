# Drop Home Works

Сайт для приёма домашних заданий: учитель выдаёт задания классам, ученики сдают работы в PDF. Учитель проверяет их и выставляет баллы.

Бэкенд $-$ `Go + PostgreSQL`.

Фронтенд (React SPA) пишется отдельно и работает по спецификации API.

- Требования $-$ [docs/decisions.md](docs/decisions.md)
- Устройство базы $-$ [docs/database.md](docs/database.md)

- API $-$ [api/openapi.yaml](api/openapi.yaml)
  - собранная спецификация и HTML-документация $-$ в [api/dist/](api/dist/)

## Запуск локально

### Требования

- Go 1.27
- Docker с Compose v2
- [mise](https://mise.jdx.dev/) $-$ по желанию (чтобы переменные из `.env` подхватывались сами)

### Первый запуск

```bash
cp .env.example .env
mkdir data
docker compose up -d
docker compose ps
```

Если пользователь не состоит в группе `docker`, команды `docker` запускаются через `sudo`.

### Переменные окружения

Сервер читает настройки только из переменных окружения, сам файл `.env` $-$ не открывает. Чтобы загрузить их из `.env` есть несколько вариантов:

- **mise:** один раз выполнить `mise trust`. Если mise подключён к shell, то переменные появятся сами в папке проекта. Иначе запускать так: `mise exec -- go run ./cmd/server`.
- **без mise:** `set -a; . ./.env; set +a` в терминале.
- **отладчик VS Code:** в `.vscode/launch.json` указать `"envFile": "${workspaceFolder}/.env"` и `"cwd": "${workspaceFolder}"`.

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `HTTP_ADDR` | нет | `:8080` | Адрес, на котором сервер принимает запросы, в виде `хост:порт` |
| `DATABASE_URL` | да | $-$ | Строка подключения к PostgreSQL |
| `STORAGE_DIR` | да | $-$ | Папка для файлов. Должна существовать и быть доступна для записи: сервер её не создаёт |
| `LOG_FORMAT` | нет | `text` | Формат логов: `text` или `json` |
| `LOG_LEVEL` | нет | `info` | Уровень логов: `debug`, `info`, `warn`, `error` |

Пустое значение считается незаданным. Если настройки неверны, сервер при старте перечисляет все ошибки и завершается с кодом 1.

### Запуск сервера

```bash
go run ./cmd/server
curl localhost:8080/api/health
```

Для **старта** сервера база необходима $-$ при старте запускаются миграции. Если база стала недоступна после запуска, `/api/health` отвечает `503` и `{"status":"unavailable"}`, а сам сервер продолжает работать и переподключается, ожидая возвращения базы.

Остановка $-$ Ctrl+C: сервер перестаёт принимать новые соединения и до 30 секунд ждёт окончания текущих запросов.

### Тесты

```bash
go test -race ./...
```

Интеграционным тестам нужна запущенная база и переменная `TEST_DATABASE_URL` (есть в `.env.example`). Она указывает на служебную базу `postgres`, а не на `cpmdb`: через неё тесты создают для каждого теста свою базу `test_...` из шаблона с миграциями и удаляют её после теста. Данные для разработки при этом не затрагиваются. Если переменная не задана, тесты с базой пропускаются (SKIP).

### База данных

- `docker compose stop` / `docker compose start` $-$ остановить и снова запустить базу.
- `docker compose down` $-$ удалить контейнер, данные остаются в томе.
- `docker compose down -v` $-$ удалить контейнер **вместе с данными**.
- Подключиться: `psql "postgres://postgres:postgres@localhost:5432/cpmdb"` или `docker compose exec db psql -U postgres -d cpmdb`.

Пользователь, пароль и имя базы задаются в `compose.yaml` и применяются только при первом создании тома. Чтобы они вступили в силу после изменения, том нужно пересоздать (`docker compose down -v`, данные пропадут).

## Генерация кода

Сгенерированные файлы лежат в git, руками их не правят: при следующей генерации правки пропадут.

### API

Спецификация — источник истины: любое изменение API сначала вносится в [api/openapi.yaml](api/openapi.yaml). После правки:

```bash
npx @redocly/cli bundle > ./api/dist/openapi.yaml                      # собрать спецификацию в один файл
go generate ./...                                                      # обновить internal/api/api.gen.go
npx @redocly/cli build-docs api/openapi.yaml -o ./api/dist/docs.html   # обновить HTML-документацию
```

Код сервера генерируется из собранного файла `api/dist/openapi.yaml`, а не из `api/openapi.yaml`: без секции `components` генератор не создаёт именованных типов. Генератор oapi-codegen подключён через `go tool`, его версия зафиксирована в `go.mod`.

### Запросы к базе

Запросы пишутся на SQL в [internal/db/queries/](internal/db/queries/), Go-код для них генерирует sqlc по схеме из [migrations/](migrations/):

```bash
sqlc generate
```

Версия sqlc зафиксирована в `mise.toml`. Без mise нужно поставить sqlc той же версии вручную.

### Миграции

Изменение схемы — новый файл `migrations/0000N_описание.sql` с секциями `-- +goose Up` и `-- +goose Down`. Миграции встроены в бинарник и применяются при старте сервера. Уже применённую миграцию не правят: изменение оформляется новой миграцией. После изменения схемы нужно перегенерировать запросы (`sqlc generate`).
